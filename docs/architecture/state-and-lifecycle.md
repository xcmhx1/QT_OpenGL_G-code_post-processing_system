# 状态与生命周期

## 1. 稳定身份与 Viewer 临时身份

系统区分两类身份：

| 身份 | 生命周期 | 用途 |
| --- | --- | --- |
| 稳定图元身份 | 贯穿文档、加工状态和派生结果 | 关联 CAD 图元、加工计划、机床轨迹和 NC |
| Viewer 临时身份 | 当前对象和显示缓存生命周期 | 渲染缓存、拾取、选择和 GPU 资源定位 |

加工状态、计划、轨迹和 NC 仅使用稳定图元身份。Viewer 临时身份仅在显示边界内使用，不跨对象生命周期保存，也不进入加工数据链。

## 2. 文档内容状态

以下操作改变 CAD 文档内容：

- 导入或清空文档；
- 新增、删除和复制图元；
- 移动、旋转、缩放、镜像等几何编辑；
- 图层和颜色修改；
- Undo/Redo。

文档内容变化后，旧几何捕获结果和基于旧文档生成的加工计划失效。批量操作作为一次业务动作推进一次内容状态，避免中间状态被误认为完整结果。

## 3. 加工上下文

加工上下文分为用户业务输入和自动分析状态。

用户业务输入包括：

- 加工启用；
- 加工方向；
- 加工起点；
- 当前加工单元序列；
- 内部线；
- 方管截面；
- 加工断面；
- 废面；
- 排序方式。

自动分析状态包括系统识别得到的截面、内部线、加工断面及其他加工分析结果。用户确认的截面、内部线、加工断面和废面优先于对应的自动分析状态。当前加工单元序列和方向由排序入口解析：普通排序尽量保留当前序列、人工方向和人工起点，智能排序忽略当前序列并重新计算。

当前有效加工上下文与 CAD 几何共同决定加工计划。选择状态和 Viewer 显示开关仅改变交互或展示，不改变加工业务输入或自动分析状态。

## 4. 加工单元序列状态

Core 根据统一加工路径及连续关系形成 `ProcessUnit` 集合。每个单元使用其全部稳定图元身份的排序规范集合作为 `ProcessUnitKey`。Application 保存并编辑唯一的 `ProcessUnitSequence`，序列位置产生连续的 `1..N` 加工编号。

加工单元插入、删除或移动后，Application 立即重排连续编号并推进加工状态 revision。智能排序结果直接替换当前序列，不保留隐藏的旧人工顺序。Viewer 中的选择范围和编号显示是该序列的交互投影，不拥有序列事实。

文档几何或连续关系变化后，旧加工单元身份和序列需要按新的 `ProcessUnitKey` 重新解析。能够匹配的单元可保留相对顺序，新增或变化的单元由普通排序补入；智能排序重新生成完整序列。

## 5. 派生结果与失效关系

三轴和四轴使用不同的派生链：

```text
三轴：ProcessPlan → NcProgram → G-code 文本
四轴：ProcessPlan → MachineTrajectory → NcProgram → G-code 文本
```

状态失效遵循上游变化使下游结果失效的原则：

| 变化 | 失效结果 | 保留内容 |
| --- | --- | --- |
| 文档几何、图层或颜色变化 | 旧加工计划及其全部下游结果 | 仍可关联的用户业务输入 |
| 加工启用、方向、起点或加工单元序列变化 | 旧加工计划及其全部下游结果 | CAD 文档内容和当前加工单元集合 |
| 内部线、加工断面或废面变化 | 旧加工计划及其全部下游结果 | CAD 图元和当前业务输入 |
| 方管截面变化 | 依赖截面的分析、计划及其下游结果 | 普通四轴所需的其他输入 |
| 排序配置变化 | 旧加工计划及其全部下游结果 | CAD 文档和加工上下文 |
| 机床运动配置变化 | 四轴机床轨迹、NC 程序和 G-code 文本 | 当前有效加工计划 |
| 纯代码格式规则变化 | G-code 文本 | 加工计划、四轴轨迹和 NC 语义 |

排序配置包括排序方式及影响计划构建的策略。机床运动配置包括旋转轴中心、安全距离、加工面 Z 修正、过切、A 轴规则和初始机床位置。纯代码格式规则包括文件、类型、图层、颜色和自定义代码的文本输出规则。

失效仅清除或拒绝使用派生结果，不反向删除用户业务输入或自动分析状态。重新生成时，系统使用当前文档、当前加工上下文和当前配置建立新结果。

## 6. 方管截面状态

方管截面的字段定义见[领域模型](./domain-model.md)。本节仅定义其来源、缺省值和失效关系。

截面输入来源优先级为：

1. 用户当前明确指定的截面参数；
2. 当前有效的自动识别结果；
3. 中心缺失时使用 `(0, 0)`。

自动识别结果不得静默覆盖用户已经确认的手动截面。用户修改截面后，所有依赖旧截面的增强分析和派生结果失效。

没有有效截面尺寸和圆角时，普通四轴排序、轨迹和 G-code 导出仍可使用旋转轴中心及运动配置继续运行。表面归属、圆角刀头方向、方管实体内部路径、加工断面、废面和增强安全位置等截面增强功能不可运行。

## 7. 已知实现差异

需求和概要设计规定：截面中心缺失时使用 `(0, 0)`。当前生产实现在没有有效截面且没有显式中心时，会使用全部加工路径的 YZ 包围盒中心作为方管中心。

该行为与当前需求不一致，后续详细设计和生产实现校准必须明确解决。在完成校准前，不能将当前包围盒中心回退视为符合 `(0, 0)` 默认规则。

当前生产实现由 Application 保存唯一 `ProcessUnitSequence`，三轴和四轴计划均生成 `ProcessUnitKey`。普通排序保留现有单元序列，智能排序重建单元序列；Viewer 按加工单元显示编号和起点方向箭头，并支持连续范围内的块内移尾。

## 8. 加工展示状态

加工顺序、方向、加工单元和计划排除项从当前有效加工计划生成显示快照。目标显示以加工单元为粒度，每个单元只显示一个编号。内部线等即时用户加工状态即使使旧计划失效，也应继续通过当前业务状态显示。

Viewer 展示快照随有效计划更新或清除。展示快照仅反映业务状态，不承担计划或加工输入的持久化职责。
