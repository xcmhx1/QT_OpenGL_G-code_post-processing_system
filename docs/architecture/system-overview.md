# 系统概要

## 1. 整体结构

系统是面向 Windows 桌面环境的 CAD/CAM 应用。用户在界面中导入和编辑 CAD 图形，设置加工输入，由应用层组织几何分析、加工规划、机床运动和 NC 生成，最后通过外部格式边界输出 G-code。

```text
用户界面
    ↓
CAD 文档与编辑
    ↓
应用业务编排
    ↓
几何 / 拓扑 / 加工分析 / 加工规划 / 机床运动 / NC 语义
    ↓
DXF、DWG、配置和 G-code 等外部格式边界
```

系统按职责划分为 UI 与桌面层、CAD 层、Application 层、Core 层和 Infrastructure 层。各层通过明确的数据边界协作，界面展示、文档事实、用户加工输入和派生加工结果分别管理。

## 2. UI 与桌面层

UI 与桌面层负责：

- 接收用户命令和参数；
- 提供菜单、选项卡、对话框和状态提示；
- 管理文件选择和用户消息；
- 通过 Viewer 展示 CAD 图形、选择状态和加工标记；
- 将用户动作交给 CAD 层或 Application 层处理。

几何事实、排序结论、机床轨迹和 NC 内容由下层业务数据提供。Viewer 仅消费显示所需的数据，不作为加工事实来源。

## 3. CAD 层

CAD 层负责：

- 维护当前 CAD 文档和原始图元；
- 维护图层、颜色和稳定图元身份；
- 执行创建、选择、删除、复制和几何编辑；
- 支持 Undo/Redo；
- 生成 Viewer 所需的显示几何和交互信息。

CAD 层保存可编辑的文档事实。加工计划、机床轨迹和 NC 语义由后续业务流程派生。

## 4. Application 层

Application 层负责：

- 从当前文档捕获核心计算所需的值对象；
- 管理用户加工状态及其版本关系；
- 组织导入后处理、分析、排序、轨迹生成和导出流程；
- 校验文档状态、加工输入和派生结果是否一致；
- 调用 Core 层能力和 Infrastructure 层边界适配；
- 将结构化结果转换为 UI 可展示的状态和消息。

Application 层是交互状态与纯业务计算之间的编排边界，不重复实现几何、拓扑、规划或文本方言规则。

## 5. Core 层

Core 层负责与界面和外部格式无关的业务计算，包括：

- 精确源几何和统一加工路径；
- 路径连通、闭环和拓扑关系；
- 方管截面、内部路径和加工断面等工艺几何；
- 三轴与四轴加工计划；
- XYZ/A 机床运动、安全移动、连续连接和过切；
- 与具体文本格式分离的 NC 语义。

Core 使用值对象作为输入和输出。Core 仅处理业务事实，不依赖 UI、CadItem、DRW 实体或外部文件对象。

## 6. Infrastructure 层

Infrastructure 层负责系统与外部数据格式之间的转换和读写，包括：

- DXF/DWG 文件边界；
- G-code 配置文件管理；
- 位图处理边界；
- NC 语义到 G-code 文本的格式化；
- 外部文件路径和内容读写。

Infrastructure 层提供格式适配，不决定加工顺序、加工方向、轨迹安全策略或工艺屏障。

## 7. 三轴与四轴能力

三轴流程从 CAD 几何和用户加工输入生成平面加工计划及 NC 语义。

普通四轴流程在有效加工路径、旋转轴中心、运动参数、加工顺序和配置基础上生成绕 X 轴、A 轴展开的轨迹。普通四轴仅使用其自身所需输入，可在没有方管截面尺寸和圆角数据时运行。

截面增强四轴在普通四轴基础上使用方管 Y/Z 尺寸、圆角半径和截面中心，支持表面归属、方管实体内部路径、加工断面、废面、圆角刀头方向和增强安全位置等能力。

## 相关需求

SCOPE-001、SCOPE-002、SCOPE-003、SCOPE-006、FILE-001、FILE-002、MACH-031、MACH-032、GCODE-010、GCODE-014。
